## 1. 目标与边界

平台面向一个采购企业和多个上游供应商，形成“需求/库存数据 → 14 日预测 → 采购建议 → 需求/计划 → 订单 → 到货 → 收货 → 对账 → 预警”的可追溯闭环。Spring Boot 是唯一业务入口和业务数据库写入方，FastAPI 只提供无状态解析与预测能力，前端负责工作台和角色化操作。

V1 范围包含四角色 RBAC、供应商/物料/仓库/库存、四类 CSV 导入、采购需求/计划/订单、供应商协同、到货/收货/对账、预警看板、审计，以及三类白名单文本解析和 14 日预测。V1 不连接真实 ERP/SRM、物流、发票或财务总账，不做自动审批、自动下单、通用聊天机器人、多租户或移动原生应用。

## 2. 用户与权限目标

| 角色 | 主要职责 | 数据边界 |
|---|---|---|
| ADMIN | 用户、角色、系统和审计管理 | 可管理平台数据，但不替代业务审批 |
| BUYER | 数据导入、预测、采购需求、计划、订单、收货和对账 | 企业采购范围 |
| SUPPLIER | 查看并反馈自身订单、到货通知和对账 | 仅绑定的 `supplier_id` |
| MANAGER | 看板、预测指标、风险和计划审批 | 只读分析加授权审批 |

前端隐藏按钮不构成安全边界，后端 JWT、角色和供应商范围必须再次校验。AI 解析结果必须预览、校验并由用户确认，不能直接改变业务事实。

## 4. 核心闭环 BCL-01

1. BUYER 导入 `demand_history.csv`、`inventory.csv` 和主数据模板，先预览再提交。
2. BUYER/MANAGER 查看物料未来 14 日预测、指标、序列和缺口建议。
3. BUYER 手工创建采购需求，或提交自然语言文本生成解析草稿。
4. 草稿经过字段/业务校验并由用户确认后进入采购需求；计划提交后由有权限人员审批。
5. 已审批计划生成采购订单，SUPPLIER 只能操作自己的订单。
6. SUPPLIER 提交到货通知，BUYER 收货；收货和库存流水保持同一业务事务。
7. 系统生成订单与实收的差异对账，异常进入预警和审计。

## 5. 非功能与安全约束

- 可复现：默认规则解析不依赖网络；没有完整 OpenAI-compatible 配置时不声称使用大模型。预测在无 XGBoost 时降级到 MA7。
- 可审计：请求 ID、导入批次、AI 解析记录、预测运行和关键状态变化应可追溯。
- 数据安全：AI 服务不持有数据库凭据；服务间使用 `X-Service-Token`；业务接口使用 JWT Bearer；CORS 仅允许显式来源。
- 运行约束：项目根目录为 `D:\论文`；Python、npm、Maven 缓存、日志、H2/MySQL 数据和运行清单放在 D 盘。
- 可用性：AI 失败不应绕过人工确认；业务服务可回到结构化表单。指标和置信度只用于解释，不直接触发自动决策。
