# 关键决策记录

本表是当前实现基线。状态为“已确认”的决策已获得用户直接指示或在用户要求“一口气做完”的范围内由 Sol Max 裁决并落实；后续改变必须记录原因、迁移和对代码、数据库、接口、测试、实验及论文的影响。

| 编号 | 决策 | 状态 | 主要理由 |
|---|---|---|---|
| ADR-001 | Vue 3 + Spring Boot 模块化单体 + 独立 FastAPI + MySQL 8；本地允许 H2 文件库 | 已确认 | 兼顾企业工程结构、开发可控和 AI/Python 实验能力 |
| ADR-002 | 浏览器只访问 Spring Boot；FastAPI 只在本机回环或 Compose 内网提供内部能力 | 已确认 | 统一鉴权、审计、事务、错误和业务校验 |
| ADR-003 | Spring Boot 是业务数据唯一读写方；FastAPI 无业务库账号且不直接写单据 | 已确认 | 防止算法绕过权限和状态机 |
| ADR-004 | V1 不引入 Redis、MQ、注册中心和微服务治理 | 已确认 | 本科项目规模无需过度设计 |
| ADR-005 | 外部数据入口固定为四类 UTF-8 CSV：供应商、物料、库存、需求历史；不宣称已对接 ERP/SRM | 已确认 | 可实现、可审计且论文口径真实 |
| ADR-006 | 预测固定 14 天；MA7 为稳定基线，XGBoost 仅在数据资格与验证胜出时采用 | 已确认 | 避免为了“智能”强行选择效果更差模型 |
| ADR-007 | 时间顺序 70/15/15 切分，验证区间三次 14 日扩展窗；记录 MAE、RMSE、MAPE，MAPE 排除真实值为 0 的分母 | 已确认 | 避免数据泄漏并保持指标可解释；不再使用规划稿中的 sMAPE 口径 |
| ADR-008 | AI 仅解析 `purchase_demand`、`plan_change`、`delivery_notice`；结构、业务、权限校验后必须用户确认 | 已确认 | AI 是受控助手，不能直接改变业务事实 |
| ADR-009 | 固定 ADMIN、BUYER、SUPPLIER、MANAGER 四角色；业务主数据由 BUYER 维护，ADMIN 只管系统用户/角色/审计 | 已确认 | 责任边界清楚，避免管理员代办业务 |
| ADR-010 | 计划、订单、到货、收货、对账采用显式状态命令；普通更新不得任意改状态 | 已确认 | 保证业务真实性、幂等和审计 |
| ADR-011 | 一个采购计划只对应一个供应商并生成一个订单；V1 不做跨供应商拆单 | 已确认 | 收敛闭环复杂度并便于验收 |
| ADR-012 | 演示、合成、回放、规则 provider 和降级结果必须显著标注 | 已确认 | 禁止把模拟结果包装成生产结果 |
| ADR-013 | 英文题目暂定 *Design and Development of a Digital and Intelligent Collaboration Platform for Enterprise Supply Chains* | 待导师确认 | 最终以学校系统为准 |
| ADR-014 | 根目录固定 `D:\论文`；缓存、运行数据和浏览器二进制均进入项目内 D 盘目录 | 已确认 | 用户明确要求避免 C 盘继续占用 |
| ADR-015 | 本地服务间令牌使用 `SCIC_AI_SERVICE_TOKEN`/`X-Service-Token`；真实密钥只从环境变量读取且不提交 | 已确认 | 固定安全边界与可运行配置 |
| ADR-016 | 可运行平台与主闭环优先，正式书面材料后置，原始证据从开发第一天持续留存 | 已确认 | 用户明确要求先完成新平台 |
| ADR-017 | 用户反馈统一使用 UAT 编号，必须复现、修改、回归、记录影响并由用户复验 | 已确认 | 防止交接口径漂移 |
| ADR-018 | 前端演示回退默认关闭，只能显式设置 `VITE_ENABLE_DEMO_FALLBACK=true` 开启且必须显示标识 | 已确认 | 防止真实接口失败被假数据掩盖 |
| ADR-019 | H2 仅用于本地候选和自动测试；最终部署结论必须来自全新 MySQL 8/Compose 实测 | 已确认 | 区分开发便利与部署证据 |
| ADR-020 | 当前发布标识为 `0.9.0-UAT-RC2`；用户 UAT、干净 Compose 和阻断验收未过前不得标记 V1.0 | 已确认 | 如实表达成熟度 |
