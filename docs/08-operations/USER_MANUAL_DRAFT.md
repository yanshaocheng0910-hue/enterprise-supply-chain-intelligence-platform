## 1. 登录与角色

打开前端地址，使用管理员、采购、供应商或管理者账号登录。开发种子账号为 `admin`、`buyer`、`supplier`、`manager`，密码均为 `123456`，仅限本地演示。登录后页面和接口会按角色显示功能，但真正权限由后端 JWT 和数据范围控制。

## 2. 采购人员操作流程

### 2.1 导入数据

1. 进入数据导入，选择 `suppliers.csv`、`materials.csv`、`inventory.csv` 或 `demand_history.csv`。
2. 确认模板版本、来源系统和文件内容，先点击“预览/校验”。
3. 查看行号、字段名和错误消息；修正引用不存在、重复或数量格式错误的行。
4. 预览无阻断错误后提交批次；保留批次号，后续可查看错误和来源。

示例文件位于 `D:\论文\samples\import`，是演示模板，不是真实企业数据。通常先导入供应商/物料，再导入库存和需求历史。

### 2.2 查看预测

进入预测页面，选择物料并发起预测。系统固定输出未来连续 14 天序列、模型、MAE/RMSE/MAPE、逐折评估、选择理由和后处理说明。数据不足或 XGBoost 不可用时显示 MA7 和降级原因；这不是错误。`lead_time` 超过 14 天时显示 `HORIZON_INSUFFICIENT`，系统不生成自动建议量。

预测是辅助决策，不能代替采购人员确认。模型选择遵循“平均验证 MAE 低于 MA7 且三个 14 日扩展窗至少胜两次”的规则，不因一次看起来更好的测试结果手工切换。

### 2.3 创建需求、计划和订单

1. 在采购需求中填写物料、数量、期望日期和优先级，保存草稿。
2. 可使用 AI 解析输入采购需求文本；检查原文、结构化字段、缺失字段和警告，修改后再确认。
3. 将需求编入采购计划，提交审批；审批通过后才能生成订单。
4. 检查供应商、价格、数量和到货日期，使用带幂等键的提交动作，避免重复订单。

AI 只支持采购需求、计划变更、到货通知三类意图。解析 `confidence` 仅供参考，始终需要人工确认；AI 不会直接写入采购单。

## 3. 供应商操作流程

供应商登录后只能看到绑定供应商的数据：

1. 查看待确认订单，执行确认或反馈。
2. 按订单提交到货通知，可录入预计到达、承运商和运单号。
3. 查看收货结果和对账差异，按权限确认或提出争议。

尝试访问其他供应商订单应被后端拒绝；如果页面出现异常，记录接口、账号、时间和请求号，不使用前端绕过。

## 4. 收货、对账与预警

采购人员在到货状态满足前置条件后选择仓库并录入收货明细。系统应在同一业务事务中更新收货、库存和库存流水；数量差异会进入对账。对账可确认、争议、解决并完成，所有动作留下操作日志。

看板和预警用于定位缺货、需求激增、延期、收货差异等问题。每条预警应展示对象、原因、建议和处理人；处理动作不能跳过状态约束。

## 5. AI 解析示例

```json
{
  "text": "请采购物料编码 MAT-CPU-01 20 件，2026-09-01 前到货，供应商 SUP-001",
  "intent_hint": "purchase_demand"
}
```

预览中确认物料、数量、日期、供应商和单位；缺失或相对日期（如“明天”）需要人工补充。未配置外部 provider 时 `provider=rule`，这是可复现的规则降级，不能对用户展示为大模型结果。

## 6. 数据、环境和已知限制

- 演示数据、回放和规则降级必须带标签，不能在报告中写成真实企业生产结果。
- 当前语义 API 路径已完成候选版联调；后续个人 UAT 发现 404 或字段不一致时仍须记录为 UAT 反馈。
- 本机未执行 Docker；最终部署前需在干净 Docker 环境验证。
- 学校 Word/Excel 模板未填；本草案不作为最终提交材料。
- 任何自动建议、预测或解析都不能跳过人工确认、业务事实校验和权限检查。
