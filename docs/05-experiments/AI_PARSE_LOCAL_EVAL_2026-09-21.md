# 本地大模型结构化解析评测（2026-09-21）
## 1. 实验目的

验证平台不是仅使用写死数据或规则冒充 AI，而是在完全本机、无业务数据外发的条件下，真实调用 Qwen2.5-1.5B，并通过“模型语义解析 + 原文证据校正 + Schema/业务校验 + 人工确认”生成受控预览。

## 2. 环境与样本

| 项目 | 值 |
|---|---|
| 模型 | Qwen2.5-1.5B-Instruct Q4_K_M |
| 推理服务 | llama.cpp b11026，`127.0.0.1:11435` |
| 接口 | FastAPI `POST /api/v1/parse` |
| Prompt 版本 | `parse-v3-intent-schema-guarded` |
| 本地安全 | `LLM_LOCAL_ONLY=true` |
| 数据集 | `ai-service/evaluation/parse_cases.json` |
| 样本构成 | 采购需求 4、计划变更 5、到货通知 3，共 12 条 |

## 3. 结果

| 批次 | 通过 | 通过率 | 平均耗时 | 说明 |
|---|---:|---:|---:|---|
| 首次运行 | 7/12 | 58.33% | 3425.299 ms | 暴露中文量词、标识符尾部标点、状态语义和模型字段校验问题 |
| 修复后回归 | **12/12** | **100%** | **3266.396 ms** | 同一固定数据集；不是扩展数据集上的泛化结论 |

原始结果分别保存在：

- `AI_PARSE_LOCAL_EVAL_2026-09-21_initial.json`
- `AI_PARSE_LOCAL_EVAL_2026-09-21.json`

## 4. 修复内容

- 对物料、订单、计划、供应商等标识符移除中文/英文句末标点；
- 补充“只”等中文数量单位，并按数量附近的原文证据校正；
- 区分已发货、预计到货与已经到货，防止模型把 ETA 误判成 ARRIVED；
- 计划“改为 300”优先解释为设定新数量，而不是增量 300；
- 模型缺失、猜测或格式错误字段由确定性原文解析补充/纠正，并在 warnings 中明确列出；
- 所有结果仍需人工确认，不能直接改变采购、库存或财务状态。

## 5. 结论边界

本次证明本地模型调用链、三类受控任务和安全降级可以运行。12 条样本规模不足以声明生产级准确率；后续论文实验应固定更大的 Ground Truth，分别报告字段准确率、整条通过率、回退率、人工修改率、冷/热启动耗时和错误分类。规则校正参与最终结果，因此 12/12 是“平台混合解析链”的通过率，不等同于裸模型准确率。
